# SpeakEase — Meeting notes (logic)

## Purpose

- Calls, lectures, interviews and online meetings become notes the user can trust and check: a short summary,
  decisions apart from proposals, action items with owner and due date, and the full transcript.
- Success signal: an hour of talk gives notes in 4-12 minutes in the background, with nothing invented for a call that
  had nothing in it. Owner decisions: spec `specs/2026-10-28-meeting-notes.md` and `decisions.md` 28-31/10 (on the
  `speakease` docs branch); build order: `ai-memory/plans/meeting-notes-build.md`.

## States and transitions

| State     | Trigger                         | Next state | Edge case                                                 |
| --------- | ------------------------------- | ---------- | --------------------------------------------------------- |
| pre-check | transcript ready                | parts      | under 20 substantive words → one line, no AI call         |
| parts     | every part noted                | merge      | a refused part keeps its words; all refused → "ai failed" |
| merge     | notes fit 1,400 words           | kind       | a refused merge keeps the notes it was given              |
| kind      | AI names a kind (or user chose) | template   | an answer naming no kind → meeting                        |
| template  | AI writes the sections          | done       | refused → "ai failed"; the transcript is still there      |

## Fixed vs flexible

- Fixed (logic the UI must not change): the pre-check runs before AI; the AI order; the meeting's text is always
  fenced; notes are AI output the user checks, with the transcript one click away (every engine measured made one to
  three number or name errors per hour).
- Flexible (UI may explore): how progress and the empty-recording line are shown, where the template switch sits.

## Open questions

- `MIN_SUBSTANTIVE_WORDS` waits for the owner's test call: `handy --meeting-notes <call.txt> --json` prints
  `substantive_words`.
- Apple Intelligence leaves owners out of action items (it wrote `- [ ] — action` on 31/10, as in round 4 where it
  wrote "em/chị/anh" instead of names). The notes are AI output to check; the transcript stays one click away.
- A meeting keeps both tracks as 16 kHz floats in memory until it ends (about 230 MB per hour per track); a very long
  meeting may need writing to disk as it goes.
- SpeakEase's "Mute while recording" mutes the speakers during a dictation; whether the meeting app's track goes
  silent for that time is not checked.
- A notes job on Qwen3.5-4B restarts the shared llama-server if subtitles or clean-up use another on-device model;
  live help (phase 4) must not run both at once.
